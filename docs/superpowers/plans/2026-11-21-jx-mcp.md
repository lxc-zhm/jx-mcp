# jx-mcp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 一个 Spring AI MCP Server：PostgreSQL 数据 DML 工具 + RAG 向量检索，单 jar 双 profile（STDIO / Streamable HTTP），配置全走环境变量。

**Architecture:** `spring-ai-starter-mcp-server-webmvc` 一个 starter 承载双传输（stdio profile 用 `spring.ai.mcp.server.stdio=true` + 非_web 应用；http profile 用 `protocol=STREAMABLE`）。工具用 `@McpTool` 注解暴露，分三组：SqlGuard 白名单校验 → CrudService（JdbcTemplate 参数化）→ @McpTool 薄壳；向量用 PgVectorStore（`initialize-schema=false`，DDL 归 db-init 特权脚本）。DDL 防御两层：JSqlParser 语句级白名单 + 数据库受限角色。

**Tech Stack:** Java 21, Spring Boot 4.1.x, Spring AI 2.1.0（BOM）, spring-ai-starter-mcp-server-webmvc / vector-store-pgvector / model-ollama / model-zhipuai / model-openai, JSqlParser 5.x, Testcontainers（pgvector/pgvector:pg17）, Maven。

**Spec:** `docs/superpowers/specs/2026-11-21-jx-mcp-design.md`

## Global Constraints

- Java 21；Spring Boot parent 4.1.x（用 Maven Central 上最新 4.1 补丁版，≥4.1.0）；`spring-ai-bom:2.1.0`；JSqlParser 用 Central 最新 5.x
- 包名统一 `com.jxmcp`；源码 UTF-8
- MCP：`spring.ai.mcp.server.type=SYNC`、`annotation-scanner.enabled=true`、name `jx-mcp`、version `0.1.0`
- 所有 SQL 值一律命名参数绑定（NamedParameterJdbcTemplate）；表/列标识符必须匹配 `^[A-Za-z_][A-Za-z0-9_]*(\.[A-Za-z_][A-Za-z0-9_]*)?$`，不匹配即抛异常
- 单条语句：SQL 含一个以上有效语句即拒绝
- `spring.ai.vectorstore.pgvector.initialize-schema=false`；维度默认 1024（bge-m3）
- 密钥只走环境变量：`DB_URL`/`DB_USER`/`DB_PASSWORD`/`ZHIPUAI_API_KEY`/`OPENAI_API_KEY`；不创建也不提交任何含真实密钥的文件
- 测试里的 PG 一律 Testcontainers `pgvector/pgvector:pg17`；Testcontainers 不用 @ServiceConnection，用 @DynamicPropertySource 显式注入连接串（少一个依赖，行为确定）

## Review Focus

实现时最可能坑到使用者的五类输入，测试必须钉死（括号内为承接任务）：

1. 值里带引号/分号/注释的注入串（`O'Brien"; DROP TABLE x; --`）→ 原样存储、原样读回，不执行、不变形（Task 3）
2. 多语句拼接（`SELECT 1; DROP TABLE t`）→ 拒绝；尾分号/尾注释算单语句放行（Task 2）
3. 无 LIMIT 的全表 SELECT → 自动强制 LIMIT（默认 1000），显式更小 LIMIT 尊重之（Task 3）
4. 向量列维度 ≠ 所配 embedding 模型维度 → 启动即失败并报清晰信息，绝不静默降级（Task 4）
5. stdio 模式 stdout 被日志污染 → console 输出禁用、日志走文件（Task 7 配置断言 + 手工冒烟）

### Task 2: SqlGuard——语句级 DML 白名单

**Files:**
- Create: `src/main/java/com/jxmcp/security/SqlGuard.java`, `src/main/java/com/jxmcp/security/SqlGuardException.java`
- Test: `src/test/java/com/jxmcp/security/SqlGuardTest.java`

**Interfaces:**
- Consumes: 无（纯 Java，JSqlParser）
- Produces:
  - `public class SqlGuardException extends RuntimeException`（构造器带 message）
  - `public final class SqlGuard`，构造器 `SqlGuard(boolean allowWhereLessMutation)`；方法：
    - `public Statement parseAndValidate(String sql)` —— 返回 `net.sf.jsqlparser.statement.Statement`，非法即抛 `SqlGuardException`（message 说明原因）
    - `public static SqlGuard.SqlType typeOf(Statement st)` —— 枚举 `SqlType { SELECT, INSERT, UPDATE, DELETE }`
  - 拒绝规则：非四类语句（含 CREATE/ALTER/DROP/TRUNCATE/GRANT/COPY/CALL/EXPLAIN 等）、多语句、`SELECT ... INTO`；UPDATE/DELETE 无 WHERE 且 `allowWhereLessMutation=false` 时拒绝

- [ ] **Step 1: 写失败测试**

`SqlGuardTest`（纯 JUnit，无 Spring）用例名：
- `select_insert_update_delete_pass`（四种各一句合法 SQL，`parseAndValidate` 不抛且 `typeOf` 正确）
- `ddl_rejected`（`CREATE TABLE t(id int)`、`ALTER TABLE t ADD c int`、`DROP TABLE t`、`TRUNCATE TABLE t`、`GRANT SELECT ON t TO u` → 各自抛 `SqlGuardException`）
- `multi_statement_rejected`（`"SELECT 1; DROP TABLE t"` 抛；`"SELECT 1;"` 与 `"DELETE FROM t WHERE id=1 -- ; DROP TABLE t"` 放行）
- `select_into_rejected`（`SELECT * INTO new_t FROM demo` 抛）
- `update_without_where_rejected_by_default`（`new SqlGuard(false)`，`UPDATE t SET a=1` 抛）
- `delete_without_where_rejected_by_default`
- `where_less_allowed_when_configured`（`new SqlGuard(true)`，两句均放行）
- `cte_delete_is_delete`（`WITH x AS (SELECT 1) DELETE FROM t WHERE id=1` 放行且 typeOf=DELETE）

- [ ] **Step 2: 跑测试确认失败**

Run: `mvn -q test -Dtest=SqlGuardTest`
Expected: FAIL（类不存在，编译错误）

- [ ] **Step 3: 实现 SqlGuard**

`CCJSqlParserUtil.parse(sql)` 得 Statement；`CCJSqlParserUtil.parseStatements(sql)` 得多语句列表，size>1 或含尾随非注释内容即拒；类型判定用 instanceof（`Select`/`Insert`/`Update`/`Delete`，其余一律拒）；`Select` 带 `getIntoTable() != null` 拒；`Update.getWhere()`/`Delete.getWhere()` 为 null 时按开关拒。CCJSqlParser 5.x 的 API 以实际 jar 为准（Statements 集合类名可能变化，以"数出有效语句数"为目标）。
